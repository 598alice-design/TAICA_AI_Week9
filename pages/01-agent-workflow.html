Unit 01 Agent Architecture

Multi-Agent 狀態機與協作架構導論

理解如何透過狀態圖（State Graph）與職責分離，解決單一 LLM 處理複雜任務時的幻覺與失控問題。

1. 概念背景與核心問題

當我們要求單一大型語言模型（LLM）同時負責「理解使用者意圖、檢索知識、驗證邏輯並給出引導式回饋」時，Prompt 往往會變得過於龐大，導致模型容易遺忘限制條件或產生幻覺。

💡 核心觀念：將龐大的單一系統拆解為多個職責單一的 Agent 節點（如 Router、Retriever、Evaluator），並透過明確的狀態轉移（State Transition）控制流程，能大幅提升系統的穩定度與可解釋性。

2. 架構流程與實作解析

一個標準的教學引導型 Multi-Agent 工作流通常包含以下三個核心階段：

  1. 意圖路由節點 (Router Node)：分析使用者輸入，判斷目前處於提問、作答還是需要提示的階段。
  2. 知識檢索與生成節點 (Worker Node)：根據當前狀態調用對應工具或知識庫，生成初步回應。
  3. 品質守門員節點 (Guardrail Node)：檢查輸出是否符合教學規範（例如：給予蘇格拉底式反問，而非直接洩漏標準答案）。
// 狀態機節點流轉示意 (State Graph Concept)
State = { user_input, current_phase, retrieved_context, final_response }

[Start] -> Router_Node(State)
  ├── if need_hint   -> Socratic_Prompt_Node(State)
  └── if verify_ans  -> Evaluation_Node(State)
-> Guardrail_Check(State) -> [End]
⚠️ 注意事項：設計迴圈（Cycle）機制時，務必設定最大重試次數（Max Iterations），避免守門員節點持續退回導致無限迴圈與資源耗盡。
